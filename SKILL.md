# human-craft

Build and scrub websites, web applications, copy (English and Arabic), source code, git repositories, and programmatic motion so that no layer reads as machine-generated. The goal is deliberate human craft: every generic default or generator tell is replaced with a specific, defensible design or engineering decision.

## When to use

- Building a new website, landing page, documentation site, dashboard, or web app that must avoid template clichés.
- Auditing and scrubbing an existing project generated by v0, Lovable, Bolt, Cursor, Claude Code, or Copilot.
- Rewriting English or Arabic UI copy to remove LLM filler phrases and translation calques.
- Designing and verifying native Arabic RTL interfaces, typography, and bilingual layouts.
- Choreographing code-generated video or canvas animations (Remotion, GSAP, Canvas 2D, Three.js).

## The 8 governing laws

1. **Specificity over generality**: Every element carries a concrete reason. "Clean and modern" is not a design decision.
2. **Decision over default**: Any unexamined framework default (Inter, Poppins, Cairo, indigo-500 to pink-500 gradients, `rounded-2xl shadow-lg`, `py-20` on every section) is treated as a tell until replaced or justified.
3. **Identity comes from constraints**: Every project starts with a one-page Direction Statement locking typography, 60/30/10 color tokens, grid proportions, imagery, motion curves, and copy voice.
4. **Intentional asymmetry over mechanical repetition**: Break symmetry to direct attention (such as a 4-column sticky index paired with an 8-column specification table) instead of repeating 3-card icon rows.
5. **Real content first**: Never design around `Lorem ipsum` or fake metrics. Mark missing facts with `[CLIENT INPUT NEEDED: ...]` and adapt the page structure.
6. **Every layer is evidence**: Reviewers inspect the DOM, CSS, bundle, git log, package.json, HTTP headers, and image metadata, not just screenshots.
7. **Detect then replace**: Deleting a tell without substituting a better domain-specific decision counts as a failure.
8. **Verify with code**: Never claim a project is clean without attaching the output of `node scripts/scan-all.mjs`.

## Non-negotiable ethical boundaries

- **Zero fabrication**: Never invent client testimonials, client logos, user counters (`10,000+ happy users`), star ratings, team members, awards, or certifications. Use `[CLIENT INPUT NEEDED: ...]` and log items in `templates/reports/client-todo.md`.
- **Provenance preservation**: Never strip content credentials (C2PA/EXIF provenance) where law, platform policy, or contract requires disclosure. `scripts/strip-metadata.sh` preserves provenance by default and requires `--strip-provenance --reason "<explanation>"` for explicit exceptions.
- **No brand impersonation**: Never copy a real third-party brand's trademarks or protected identity.

## The 7 workflow phases

Execute these phases in order, loading one workflow file at a time:

1. **Phase 0 - Intake** (`workflow/00-intake.md`): Complete `templates/brief/client-brief.md` and `content-inventory.md`. Record missing client data in `client-todo.md`.
2. **Phase 1 - Audit** (`workflow/01-audit.md`): Run `node scripts/scan-all.mjs <target>` and record baseline counts in `templates/reports/audit-report.md`.
3. **Phase 2 - Direction** (`workflow/02-direction.md`): Pick one of the 12 archetypes in `references/directions/` and complete `templates/direction/direction-statement.md`.
4. **Phase 3 - Build** (`workflow/03-build.md`): Define tokens in `templates/tokens/` first, then build semantic components (with all 5 states: ideal, empty, loading, error, overflow) and pages.
5. **Phase 4 - Scrub** (`workflow/04-scrub.md`): Replace every S0, S1, and S2 tell across visuals, copy, markup, code, assets, and git history.
6. **Phase 5 - Verify** (`workflow/05-verify.md`): Re-run `node scripts/scan-all.mjs <target>`, test `320px`, `768px`, and `1440px` viewports, test keyboard navigation, and verify RTL rules.
7. **Phase 6 - Handoff** (`workflow/06-handoff.md`): Produce `templates/reports/handoff.md`, `scrub-report.md`, and `client-todo.md`.

## Severity gate

| Level | Meaning | Examples | Release threshold |
|---|---|---|---|
| **S0** | Explicit machine or template fingerprint | `Lorem ipsum`, `href="#"`, `example.com`, `.cursorrules`, `CLAUDE.md`, `lovable-tagger`, `gptengineer.js`, fake testimonials, Arabic `letter-spacing > 0` | **0 allowed** |
| **S1** | High-confidence AI tell | Indigo-violet-pink hero gradients, `bg-clip-text` headlines, sparkle badges, banned phrases (`elevate`, `seamless`, `ارتقِ بتجربتك`, `حلول مبتكرة`), 3 identical icon cards | **0 allowed** |
| **S2** | Medium structural or stylistic habit | Uniform `py-20` section padding, generic `handleClick` names, redundant comments (`// Initialize state`), uncalibrated default font stacks | Below cap in `patterns/severity-map.json` with written justification |
| **S3** | Soft stylistic signal | Minor conventions logged for review | Documented in handoff report |

## Output contract

When completing a build or scrub task with `human-craft`, always deliver:

1. The completed Direction Statement (`direction-statement.md`).
2. The built or scrubbed project files with zero S0 and zero S1 findings.
3. The captured output of `node scripts/scan-all.mjs <target>` proving `S0 = 0` and `S1 = 0`.
4. The `client-todo.md` list of any `[CLIENT INPUT NEEDED]` items that require real client data.
